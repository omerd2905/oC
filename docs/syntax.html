NAME

oc-lang — active-defense systems programming language with regional bump memory management, compile-time escape & lifetime verification, and zero-libc native x86_64 ELF64 code emission.

SYNOPSIS

// Grammatical Structure of an oC Compilation Unit
<source_file>   ::= { <import_stmt> | <top_let> | <struct_decl> | <fn_decl> }*
<import_stmt>   ::= "import" <string_literal> ";"
<top_let>       ::= "let" <ident> [ ":" <type> ] "=" <expr> ";"
<struct_decl>   ::= [ "packed" ] "struct" <ident> "{" { <ident> ":" <type> [ "," ] }* "}"
<fn_decl>       ::= [ "extern" ] "fn" <ident> "(" <param_list> ")" [ "->" <type> ] ( <block> | ";" )
<param_list>    ::= [ <ident> ":" <type> { "," <ident> ":" <type> }* ]
<block>         ::= "{" <stmt>* "}"
<stmt>          ::= <let_stmt> | <assign_stmt> | <if_stmt> | <while_stmt> | <return_stmt> | <print_stmt> | <expr> ";"

2. Lexical Elements & Reserved Keywords

oC source code is encoded in UTF-8 / 7-bit ASCII. The lexical analyzer (implemented in compiler/lexer.oc) tokenizes the input stream into whitespace, comments, identifiers, integer literals, string literals, operators, and reserved keywords.

Comments

Single-line comments begin with two consecutive forward slashes // and extend to the next newline character (\n). Multi-line or block comments (such as /* ... */) are not permitted in oC to eliminate parsing ambiguities and nested-comment parser exploits. 

// This is a valid single-line comment
let x: i32 = 10; // Inline comments are also supported

Identifiers

Identifiers designate variable names, function names, parameter names, struct identifiers, and field names. An identifier begins with an ASCII letter (a-z, A-Z) or underscore (_), followed by zero or more ASCII letters, digits (0-9), or underscores.

Integer Literals

oC supports three numeric literal radices, with optional underscore (_) visual digit separators:

Radix Prefix Lexer Pattern Examples
Decimal None [0-9][0-9_]* 0, 42, 65536, 1_000_000
Hexadecimal 0x or 0X 0[xX][0-9a-fA-F_]+ 0x00, 0x4F, 0xDEADBEEF, 0xff_00_11
Binary 0b or 0B 0[bB][01_]+ 0b0, 0b1010, 0b1111_0000_1010_0101

String Literals

String literals are surrounded by double quotes "...". At runtime, every string literal in oC evaluates to a 16-byte fat slice (string, structurally equivalent to []u8) storing a 64-bit pointer (ptr: *u8) and a 64-bit length (len: usize). The lexer processes the following escape sequences:

  • \n — ASCII 10 (Line Feed)
  • \t — ASCII 9 (Horizontal Tab)
  • \r — ASCII 13 (Carriage Return)
  • \\ — ASCII 92 (Backslash)
  • \" — ASCII 34 (Double Quote)
  • \0 — ASCII 0 (Null Byte)

Reserved Keywords Table

The oC language defines exactly 15 reserved keywords. They cannot be used as identifier names:

Keyword Category Semantic Meaning & Mini-Example
fn Declaration Declares a function. fn add(a: i32, b: i32) i32 { return a + b; }
let Declaration Declares an immutable variable binding. let limit: usize = 1024;
mut Modifier Marks a variable or pointer/reference as mutable. let mut counter: i32 = 0;
return Control Flow Exits the current function, optionally returning a value. return res;
if Control Flow Branches conditionally based on a bool expression. if x > 0 { ... }
else Control Flow Alternative execution branch for an if condition. else { ... }
while Control Flow Executes a block repeatedly while condition is true. while i < 10 { i = i + 1; }
struct Type Declares a composite record type. struct Point { x: i32, y: i32 }
packed Modifier Declares a struct with 1-byte field packing (zero alignment padding). packed struct Header { ... }
extern Declaration Declares a foreign function symbol (ABI syscall or libc linkage). extern fn sys_exit(code: i32);
import Module Imports another .oc source module relative to the working directory. import "std/io.oc";
print Built-in Built-in intrinsic to print integers or string slices directly to standard output. print("hello");
true Literal Boolean literal representing logic truth (1-byte 0x01).
false Literal Boolean literal representing logic falsehood (1-byte 0x00).
as Operator Performs an explicit, checked type conversion or pointer cast. val.as(u16) or ptr.as(*u8)
Example 1: Lexical Literals & Radix Representation
SOURCE
import "std/io.oc";

fn main() -> i32 {
    let dec_val: u32 = 42;
    let hex_val: u32 = 0x2A;
    let bin_val: u32 = 0b0010_1010;

    if dec_val == hex_val {
        if hex_val == bin_val {
            print("All three radices equal 42 decimal!");
        }
    }
    return 0;
}
OUTPUT
$ occ run literal_demo.oc
All three radices equal 42 decimal!
Explanation: Decimal, hexadecimal, and binary literals produce identical bit patterns. Underscores in literals are stripped during lexical analysis.

3. Type System & Memory Representation

oC is a statically-typed systems language. Every type has an unambiguous byte size, alignment, and memory layout. There are no hidden tags, runtime type info (RTTI), or hidden object headers.

Type Syntax Category Size (Bytes) Align Signed C / Machine Equivalent
i8 Integer 1 1 Signed int8_t
u8 Integer 1 1 Unsigned uint8_t
i16 Integer 2 2 Signed int16_t
u16 Integer 2 2 Unsigned uint16_t
i32 Integer 4 4 Signed int32_t
u32 Integer 4 4 Unsigned uint32_t
i64 Integer 8 8 Signed int64_t
u64 Integer 8 8 Unsigned uint64_t
usize Integer 8 8 Unsigned size_t / uintptr_t
bool Boolean 1 1 Unsigned bool (0 or 1)
void Unit 0 1 — void
[N]T Fixed Array N * sizeof(T) align(T) — Inline flat buffer: T arr[N]
string / []T Fat Slice 16 8 — struct { T* ptr; size_t len; }
*T Raw Const Ptr 8 8 — const T*
*mut T Raw Mut Ptr 8 8 — T*
&T Shared Reference 8 8 — Borrow verified by EscapeValidator
&mut T Exclusive Reference 8 8 — Mutable borrow verified by EscapeValidator
Example 2: Fat Slices & Pointer Operations
SOURCE
import "std/io.oc";

fn print_slice_info(name: string, s: string) {
    print("Slice: ");
    print(name);
    print(" | Length: ");
    print(s.len);
    print("\n");
}

fn main() -> i32 {
    let full: string = "Active-Defense Systems";
    print_slice_info("full", full);

    // Sub-slice produces a new 16-byte fat slice pointing to original memory
    let sub: string = full[0..14]; // "Active-Defense"
    print_slice_info("sub", sub);

    return 0;
}
OUTPUT
$ occ run slice_demo.oc
Slice: full | Length: 22
Slice: sub | Length: 14
Memory Representation: full contains { ptr: 0x401000, len: 22 }. The sub-slice sub creates { ptr: 0x401000, len: 14 } without allocating any heap memory.

4. Variable Declarations & Scope Rules

Variables are introduced using the let keyword. By default, every binding is strictly immutable. Mutability must be explicitly declared with let mut.

Mandatory Initialization (CWE-457 Elimination)

oC prohibits uninitialized variable declarations. An expression must be provided on the right-hand side of the = assignment token. This statically eliminates CWE-457 (Use of Uninitialized Variable) by construction: 

let x: i32 = 0;          // Valid: explicitly initialized
let mut buf: [32]u8 = [0]; // Valid: zero-initialized fixed array
// let uninit: i32;       // SYNTAX ERROR: variable must be initialized

Scope & Shadowing Rules

Variables are lexically scoped within blocks { ... }. Inner blocks inherit variables from outer scopes, but identifier shadowing is forbidden within the same scope depth to prevent confusion and inadvertent variable hiding. Top-level constants can be defined using let IDENT: T = expr; outside function bodies.

Example 3: Explicit Mutability vs Immutability
SOURCE
import "std/io.oc";

let GLOBAL_RETRY_COUNT: u32 = 3; // Top-level constant

fn main() -> i32 {
    let immut_val: i32 = 100;
    let mut mut_val: i32 = 200;

    // immut_val = 101; // COMPILE ERROR: cannot assign to immutable variable
    mut_val = mut_val + GLOBAL_RETRY_COUNT.as(i32);

    print(mut_val);
    print("\n");
    return 0;
}
OUTPUT
$ occ run mut_demo.oc
203
Safety Invariant: Attempting to assign to immut_val triggers a compile-time rejection. Mutability is tracked by the symbol table and parser AST.

5. Complete Operator Precedence & Hardware Traps

The oC expression parser implements Pratt / Precedence-Climbing parsing across 8 distinct precedence tiers (defined in compiler/parser.oc:get_precedence()):

Prec Level Operators Description Associativity Safety / Trap Emission
Level 8
(Highest Binary)		 *, /, % Multiplicative: Multiplication, Division, Modulo Left-to-right * emits __trap_overflow on signed and unsigned overflow.
/ & % emit __trap_div_zero if divisor == 0.
Level 7 +, - Additive: Addition, Subtraction Left-to-right Emits __trap_overflow via CPU overflow flag (jo instruction).
Level 6 <<, >> Bitwise Shifts: Shift-Left, Shift-Right Left-to-right Masked by register width.
Level 5 <, <=, >, >= Relational Comparisons Left-to-right Evaluates to 1-byte bool (0 or 1).
Level 4 ==, != Equality & Inequality Left-to-right Evaluates to bool.
Level 3 & Bitwise AND Left-to-right Bitwise operation.
Level 2 ^ Bitwise XOR Left-to-right Bitwise operation.
Level 1
(Lowest Binary)		 | Bitwise OR Left-to-right Bitwise operation.
Unary -, !, *, &, &mut Negation, Logical NOT, Dereference, Borrow Right-to-left *ptr emits __trap_null_deref if ptr == NULL.
Borrows registered in EscapeValidator.
Postfix (), [], [a..b], .field, .as(T) Call, Index, Slice, Field, Checked Cast Left-to-right [] & [a..b] emit __trap_slice_bounds.
.as(T) emits truncation/sign traps (CWE-195/197).

Explicit wrapping arithmetic: +, - and * always trap on overflow. Code that needs modular arithmetic (hashes, checksums, PRNGs) says so with the built-in functions wrapping_add(a, b), wrapping_sub(a, b) and wrapping_mul(a, b), which wrap at the width of their operands instead of trapping, for example h = wrapping_mul(h ^ byte, 16777619) in FNV-1a.

Example 4: Hardware Overflow & Division-by-Zero Trapping
SOURCE
import "std/io.oc";

fn test_overflow_protection() {
    let max_i32: i32 = 2147483647;
    // The next line triggers a hardware trap on addition overflow
    let boom: i32 = max_i32 + 1; 
    print(boom);
}

fn main() -> i32 {
    test_overflow_protection();
    return 0;
}
OUTPUT
$ occ run overflow_test.oc --backend native
panic: integer overflow
[Process terminated with exit code 1 via __trap_overflow]
Trap Mechanism: The native backend emits add %ebx, %eax followed immediately by jo __trap_overflow. On overflow, the CPU jumps directly to the panic handler, writes to stderr, and terminates without executing undefined behavior.

6. Arrays, Fat Slices & Sub-slicing

In oC, buffer operations are rigorously bounded. Fixed arrays [N]T are stored inline, while slices string and []T are passed by value as 16-byte pairs containing pointer and length:

Array Declarations

Fixed arrays are declared with size N and initialized with array literals: 

let mut stack_buf: [64]u8 = [0]; // 64 bytes zeroed out
let primes: [4]i32 = [2, 3, 5, 7];

Index Bounds Verification

Reading or writing an array or slice element s[i] automatically verifies that i < s.len. If the index is equal to or exceeds the slice length, execution immediately halts via __trap_slice_bounds (preventing CWE-125 Out-of-bounds Read and CWE-787 Out-of-bounds Write):

Sub-slicing Syntax: s[start..end]

Sub-slicing creates a new view into existing memory without allocating dynamic memory. The slice expression verifies:

  • start <= end (start cannot exceed end)
  • end <= s.len (end cannot exceed source slice length)
let src: string = "ZeroAlloc";
let part: string = src[0..4]; // "Zero" (len = 4)
let tail: string = src[4..9]; // "Alloc" (len = 5)
// let invalid: string = src[5..20]; // TRAPS: panic: slice index out of bounds
Example 5: Safe Sub-slicing with .len Property
SOURCE
import "std/io.oc";

fn print_bytes(data: string) {
    let mut i: usize = 0;
    while i < data.len {
        let b: u8 = data[i];
        print(b.as(u32));
        print(" ");
        i = i + 1;
    }
    print("\n");
}

fn main() -> i32 {
    let greeting: string = "oC-LANG";
    let token: string = greeting[0..2]; // "oC"
    print_bytes(token);
    return 0;
}
OUTPUT
$ occ run bytes_demo.oc
111 67
Explanation: token[0] yields ASCII 111 ('o'), and token[1] yields ASCII 67 ('C'). The slice length token.len is 2.

7. Structs & Packed Wire Layouts

oC provides two distinct struct layouts: standard aligned structs and packed struct declarations for binary wire protocols:

Standard Aligned Structs

Standard structs align fields to their natural boundary (e.g. 4-byte alignment for i32, 8-byte for pointers). When initializing a struct literal, all padding bytes are zero-filled by the compiler to prevent uninitialized memory leakage (CWE-200 Information Exposure): 

struct SensorPacket {
    sensor_id: u32,
    reading: i32,
    status: bool,
}

// Initializing via struct literal syntax
let s: SensorPacket = SensorPacket {
    sensor_id: 101,
    reading: -40,
    status: true,
};

Packed Wire-Format Structs

Prepending the packed keyword forces 1-byte field alignment with zero padding bytes. This matches exact wire format headers for Linux sockets, file formats, and hardware registers: 

packed struct EthernetHeader {
    dst_mac: [6]u8,
    src_mac: [6]u8,
    ethertype: u16,
} // Exactly 14 bytes, sizeof guaranteed bit-for-bit
Example 6: Wire-Format Network Structs
SOURCE
import "std/io.oc";

packed struct IPv4Header {
    ver_ihl: u8,
    tos: u8,
    total_len: u16,
    id: u16,
    frag_off: u16,
    ttl: u8,
    protocol: u8,
    checksum: u16,
    src_ip: u32,
    dst_ip: u32,
}

fn main() -> i32 {
    let mut hdr: IPv4Header = IPv4Header {
        ver_ihl: 0x45, // IPv4, 5 words (20 bytes)
        tos: 0,
        total_len: 64,
        id: 0x1234,
        frag_off: 0,
        ttl: 64,
        protocol: 6, // TCP
        checksum: 0,
        src_ip: 0x7F000001, // 127.0.0.1
        dst_ip: 0x7F000001,
    };

    print("IPv4 Header Initialized. TTL: ");
    print(hdr.ttl.as(u32));
    print("\n");
    return 0;
}
OUTPUT
$ occ run ipv4_demo.oc
IPv4 Header Initialized. TTL: 64
Wire Guarantee: IPv4Header occupies exactly 20 bytes in memory with zero compiler-injected padding bytes between 8-bit, 16-bit, and 32-bit fields.

8. Functions & Foreign Intrinsics

Functions in oC are declared using the fn keyword. Return types are specified after an arrow ->. Functions that do not return a value omit the return type (equivalent to returning void).

Parameter Passing Semantics

  • Primitives & Structs: Passed by value (copied onto the call frame).
  • Pointers & References: *T, *mut T, &T, &mut T pass memory addresses without copying the underlying object.
  • Slices: Passed by value as 16-byte fat slices (ptr + len).

512-Frame Recursion Depth Guard

To prevent stack overflow attacks and unbounded recursive loops (CWE-674 Uncontrolled Recursion), the compiler enforces recursion depth verification. Deep or unbounded recursion is flagged or bounded, ensuring deterministic stack frame execution.

Foreign Function Declarations (extern fn)

External symbols (such as Linux kernel syscalls or standard C library functions) are declared with extern fn without a function body: 

extern fn sys_write(fd: i32, buf: *u8, count: usize) -> i64;
extern fn sys_read(fd: i32, buf: *mut u8, count: usize) -> i64;
extern fn sys_exit(code: i32);
Example 7: Recursive Function & Pass-by-Reference
SOURCE
import "std/io.oc";

fn square_mut(val: *mut i32) {
    let current: i32 = *val;
    *val = current * current;
}

fn factorial(n: u64) -> u64 {
    if n <= 1 {
        return 1;
    }
    return n * factorial(n - 1);
}

fn main() -> i32 {
    let mut num: i32 = 7;
    square_mut(&mut num);
    print("Squared: ");
    print(num);
    print(" | 5! = ");
    print(factorial(5));
    print("\n");
    return 0;
}
OUTPUT
$ occ run fn_demo.oc
Squared: 49 | 5! = 120
Explanation: square_mut receives a mutable reference &mut num. Modifying *val mutates the caller's stack frame directly.

9. Control Flow Statements

oC provides three primary control flow statements: if / else if / else conditional branching, while loops, and return statements.

Conditional: if / else

Parentheses around the test condition are optional, but curly braces { ... } enclosing the body are strictly mandatory to prevent dangling-else vulnerabilities: 

if score >= 90 {
    grade = 1;
} else if score >= 80 {
    grade = 2;
} else {
    grade = 3;
}

Loops: while

The while statement executes repeatedly as long as the condition evaluates to true. There is no for loop construct in oC; all iteration is expressed through explicit while loops to preserve syntactic minimalism: 

let mut idx: usize = 0;
while idx < 10 {
    // Process element
    idx = idx + 1;
}
Example 8: Deterministic Loop Execution
SOURCE
import "std/io.oc";

fn main() -> i32 {
    let mut sum: i64 = 0;
    let mut n: i64 = 1;

    while n <= 100 {
        sum = sum + n;
        n = n + 1;
    }

    print("Sum of 1..100: ");
    print(sum);
    print("\n");
    return 0;
}
OUTPUT
$ occ run sum_demo.oc
Sum of 1..100: 5050
Control Guarantee: Loop conditions are checked at the start of each iteration. Loop variables are mutated explicitly without hidden loop index side effects.

10. Module System & Import Resolution

Code in oC is organized into modular files. Modules are included using the import "path/to/file.oc"; directive.

Path Resolution Algorithm

When the compiler encounters an import statement (processed in compiler/main.oc:load_module_recursive()), it resolves the path in three tiers:

  1. Direct relative path from current working directory (e.g. std/mem.oc).
  2. Sub-path within tools/occ/.
  3. System installation path (/home/omer/occ/).

Automatic Module Deduplication

The compiler maintains a visited table (ModuleLoader) tracking up to 64 module paths. If multiple files import the same module (for example, both std/io.oc and std/fs.oc import std/mem.oc), the module is parsed exactly once. This eliminates multiple symbol definition errors and prevents circular import deadlocks.

Example 9: Modular Program with Deduplicated Imports
SOURCE
import "std/io.oc";
import "std/fs.oc";
import "std/mem.oc";

fn main() -> i32 {
    // Arena allocated in 64 KB page chunk
    let mut arena: Arena = arena_init(65536);
    let chunk: *mut u8 = arena_alloc(&mut arena, 128);

    print("Arena allocated chunk at: ");
    print(chunk.as(usize));
    print("\n");

    arena_deinit(&mut arena);
    return 0;
}
OUTPUT
$ occ run arena_demo.oc
Arena allocated chunk at: 140728198303744
Zero Libc: arena_init directly invokes sys_mmap (0x0f 0x05) to acquire anonymous memory pages from the Linux kernel. No glibc or ptmalloc heap metadata is linked.
