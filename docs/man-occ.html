NAME

occ — self-hosted zero-libc oC compiler and native x86_64 ELF64 generator.

SYNOPSIS

occ <build|run> input.oc [-o output] [-O1|-O2|-O3] [--backend <c|native>]

DESCRIPTION

occ is the primary compiler driver for the oC systems programming language. Engineered from the ground up without libc or runtime dependencies, occ compiles entire programs using regional bump arenas, validates lifetime and borrow constraints at compile time via EscapeValidator, and generates either highly-optimized C11 code or standalone Linux x86_64 ELF64 binaries.

Compiler Architecture Pipeline

+-----------------------------------------------------------------------------------+ | OCC PIPELINE ARCHITECTURE | +-----------------------------------------------------------------------------------+ | [Input .oc Files] | | | | | v | | [ModuleLoader] ---> Recursive import resolution, 64-module cycle deduplication | | | | | v | | [Lexer] ---> 15 Keywords, radices (0x, 0b), string escapes, 8-prec tokens| | | | | v | | [Parser AST] ---> Pratt precedence climbing, struct layouts, fat slice nodes | | | | | v | | [EscapeValidator] -> Active defense: stack-escape, UAF, cross-arena borrow check| | | (Zero runtime cost: 0.00 ns overhead) | | +------------------------------------+ | | | | | | v v | | [--backend c (Default)] [--backend native] | | - C11 Transpiler - 1-Pass x86_64 Machine Code Emitter | | - Runtime bounds asserts - Direct Linux Syscalls (0x0f 0x05) | | - Host GCC pipeline (-O1/-O2/-O3) - ELF64 Header & Section Assembler | | - Vectorized SIMD binaries - Hardware Traps (__trap_overflow, bounds) | | - Dynamic / Static C binary - Standalone Static ELF64 (< 5 KB, 0 libc) | +-----------------------------------------------------------------------------------+

The compilation process proceeds through four distinct, deterministic phases:

  1. Module Ingestion & Deduplication: Starting at the root compilation unit, ModuleLoader scans top-level import statements, resolves relative paths, and maintains a 64-entry visited registry to prevent circular imports or redundant parsing.
  2. Lexical & Syntactic Analysis: The Pratt parser creates a structured AST rooted at NODE_PROGRAM, holding function declarations, struct definitions, and typed expressions. All allocations occur inside a 32 MB regional bump arena without heap fragmentation.
  3. Active Safety Validation (EscapeValidator): Before any code emission, the AST is verified for memory safety. The validator analyzes variable lifetimes, detects pointers escaping stack frames, tracks arena lifetimes (flagging Use-After-Free if variables are used after arena_reset or arena_deinit), and catches cross-arena escapes. Violations halt the build immediately with exit code 1.
  4. Backend Code Generation: The AST is dispatched to either the optimizing C11 backend or the native machine-code generator.

COMMANDS

occ accepts one of two primary subcommands:

build <input.oc>

Compiles the specified source file and its imported dependencies into an executable binary. If -o <output> is omitted, the compiler outputs the binary to a.out in the current directory.

Subcommand: build
SOURCE
$ occ build examples/native_fibonacci.oc -o /tmp/native_fib --backend native
OUTPUT
$ ls -lh /tmp/native_fib
-rwxr-xr-x 1 omer users 4.7K Nov  7 19:20 /tmp/native_fib
Outcome: A standalone, 4.7 KB static ELF64 executable is produced with zero reliance on libc.so.

run <input.oc>

Compiles the source file to a temporary location (default: /tmp/occ_run_bin), executes the binary immediately, automatically removes the temporary binary upon termination, and propagates the child program's exact exit status code back to the caller.

Subcommand: run
SOURCE
$ occ run examples/core_suite.oc
OUTPUT
$ occ run examples/core_suite.oc
=== oC Core Suite: Regional Memory, Strings, & Sockets ===
[1/4] Regional bump arena alloc/reset test... PASS
[2/4] Fat slice indexing & sub-slicing test... PASS
[3/4] Socket networking & loopback echo... PASS
[4/4] Hardware integer overflow trap... PASS
All 4 suites completed successfully.
Convenience: Ideal for test suites, scripts, and continuous integration workflows.

OPTIONS & COMPILER FLAGS

The compiler supports the following command-line flags and parameters:

Flag Arguments Default Description & Behavioral Details
-o <path> a.out (build)
/tmp/occ_run_bin (run)		 Specifies the output binary path. The path is verified by is_safe_path() against shell metacharacters (;, &, |, `, $, >, <, quotes) to prevent command injection.
--backend native | c c Selects the code generation backend. native emits direct x86_64 ELF64 machine code; c transpiles to C11 and invokes host GCC.
-O1 None Disabled Enables level 1 optimization in the C backend. Passed directly to host GCC.
-O2 None Disabled Enables level 2 optimization in the C backend (loop unrolling, instruction scheduling, and vectorization).
-O3 None Disabled Enables aggressive level 3 optimization in the C backend, including auto-vectorization across mathematical loops.

BOOTSTRAP & SELF-HOSTING

occ is 100% self-hosted. The entire compiler is written in oC itself and builds itself without any external language tools.

Stage 2 == Stage 3 Bit-for-Bit Verification

Deterministic compilation is verified via a 3-stage bootstrap pipeline executed by ./showcase.sh: 

# 1. Stage 1 compiler builds compiler/main.oc into Stage 2 binary
$ occ build compiler/main.oc -o /tmp/occ_stage2

# 2. Stage 2 compiler builds compiler/main.oc into Stage 3 binary
$ /tmp/occ_stage2 build compiler/main.oc -o /tmp/occ_stage3

# 3. Bit-for-bit checksum comparison
$ cmp /tmp/occ_stage2 /tmp/occ_stage3
# Output: Exit code 0 (Identical bitstreams, zero diff bytes)

When cmp returns 0, the compiler is proven to be an idempotent, self-hosting fixed-point.

Regional Arena Memory Footprint

The entire self-hosted compilation of all 10 compiler modules is completed inside a single 32 MB regional bump arena initialized at startup via: 

let mut arena: Arena = arena_init(33554432); // 32 megabytes via sys_mmap

The 10 modular components parsed and compiled are:

  • std/io.oc — Low-level terminal I/O and integer-to-string formatters
  • std/fs.oc — POSIX file reading, writing, and unlinking syscall wrappers
  • std/mem.oc — sys_mmap regional bump arena and scrubbing allocators
  • compiler/token.oc — Lexical token tags and token structures
  • compiler/lexer.oc — Deterministic lexical scanner and keyword lookup
  • compiler/ast.oc — AST node representations and allocation arena helpers
  • compiler/parser.oc — Pratt expression parser & EscapeValidator
  • compiler/codegen.oc — C11 backend code generator and type mapper
  • compiler/elf.oc — Direct x86_64 machine code generator and ELF64 serializer
  • compiler/main.oc — Driver, path security sanitizer, and CLI option processor

DIAGNOSTICS & EXIT CODES

Exit Status Codes

Exit Code Meaning Causes
0 Success Successful build or successful program execution with return code 0.
1 Compiler / Execution Error Parse error, EscapeValidator memory safety violation, unsafe CLI path, native ELF emission failure, or child program termination via hardware trap (SIGILL / SIGTRAP).
N (2..255) Child Return Code In run mode, non-zero exit code returned by the compiled program.

Compile-Time Active Defense Rejections

The EscapeValidator outputs clear diagnostic messages indicating the exact variable and lifetime boundary violated:

Diagnostic: Stack Reference Escape Rejected
SOURCE
// examples/bad_stack_escape.oc
fn leak_stack() *mut i32 {
    let mut local: i32 = 42;
    return &mut local; // Illegal stack address escape
}
OUTPUT
$ occ build examples/bad_stack_escape.oc
error: cannot return reference to local stack variable 'local'
[occ terminated with exit code 1]
Prevention: CWE-562 (Return of Stack Variable Address) is completely prevented before any assembly or C code is generated.
Diagnostic: Use-After-Free via Arena Reset Rejected
SOURCE
// examples/exploits/UAF_Arena_Reset.oc
let mut a = arena_init(4096);
let ptr = arena_alloc(&mut a, 64);
arena_reset(&mut a);
ptr[0] = 0xAA; // Illegal access after arena invalidation
OUTPUT
$ occ build examples/exploits/UAF_Arena_Reset.oc
error: use-after-free: variable 'ptr' used after arena 'a' was reset
[occ terminated with exit code 1]
Prevention: CWE-416 (Use After Free) is eliminated statically at compile time with 0.00 ns runtime cost.
