NAME

oc-std, oc-syscalls — Core runtime primitives, regional arena memory allocators, hardened filesystem abstractions, network wire routines, checked math, and direct Linux x86_64 kernel syscall intrinsics.

OC-SYSCALLS(2) — Direct Linux x86_64 Syscalls (Zero-Libc ABI)

Unlike traditional C/C++ runtimes that require dynamic linking against libc.so.6 (or bundling a 850 KB static musl/glibc runtime), the occ compiler emits the direct x86_64 kernel machine code instruction sequence (0x0f 0x05) directly into standalone static ELF executables.

Kernel Transition: oC bypasses userspace wrappers entirely. The occ backend (compiler/elf.oc) assigns register operands according to the System V AMD64 Syscall Calling Convention and emits a 2-byte syscall instruction.

Linux x86_64 kernel ABI register convention strictly enforced by occ:

Register Syscall Role oC Runtime Binding
%rax Syscall Number & Kernel Return Value Loaded with literal syscall number before syscall; holds return value / error code (< 0 is -errno)
%rdi Argument 1 1st parameter (e.g. file descriptor fd or memory address addr)
%rsi Argument 2 2nd parameter (e.g. buffer pointer buf or length len)
%rdx Argument 3 3rd parameter (e.g. byte count count or protection flags prot)
%r10 Argument 4 4th parameter (Kernel replaces %rcx with %r10 for syscall ABI, e.g. flags)
%r8 Argument 5 5th parameter (e.g. backing file descriptor fd for mmap)
%r9 Argument 6 6th parameter (e.g. file offset off for mmap)

Example: Standalone x86_64 Direct Syscalls (Zero Libc)
SRC: sys_direct.oc 
// Direct kernel invocation without libc runtime
extern fn sys_write(fd: i32, buf: *u8, count: usize) -> i64;
extern fn sys_mmap(addr: usize, len: usize, prot: i32, flags: i32, fd: i32, off: usize) -> *mut u8;
extern fn sys_munmap(addr: *mut u8, len: usize) -> i32;

fn main() -> i32 {
    let msg: string = "[KERNEL] Direct x86_64 syscall execution verified!\n";
    sys_write(1, msg.ptr, msg.len);

    // Map 4096 bytes anonymously (PROT_READ|PROT_WRITE=3, MAP_PRIVATE|MAP_ANONYMOUS=34)
    let page: *mut u8 = sys_mmap(0, 4096, 3, 34, -1, 0);
    *page = 79; // Store ASCII 'O'
    let unmap_rc: i32 = sys_munmap(page, 4096);
    return unmap_rc;
}
TERMINAL: Direct Execution 
$ occ build sys_direct.oc -o /tmp/sys_direct --backend native
$ /tmp/sys_direct
[KERNEL] Direct x86_64 syscall execution verified!
$ echo $?
0
Active Defense ABI Guarantee: Standalone ELF binary contains only .text, .rodata, and an entry-point stub that sets up %rdi and executes sys_exit upon return from main. There is no dynamic linker (/lib64/ld-linux-x86-64.so.2), rendering shared library hijacking (e.g. LD_PRELOAD) completely impossible.

OC-OS(3) — `std/os.oc` Canonical Constants, Targets & Portability

std/os.oc defines every OS flag oC programs pass to the intrinsics above. The values are canonical Linux x86_64 numbers: --backend native emits them unchanged, and the C backend preamble translates them to the host's own flags (POSIX mmap/MAP_ANON on macOS and the BSDs, VirtualAlloc/_open/_O_BINARY on Windows, sa_len socket addresses on macOS/BSD). Source code therefore never contains #ifdef-style host checks.

OC_TARGET_* identifiers

let OC_TARGET_OTHER: i32 = 0; let OC_TARGET_LINUX_X86_64: i32 = 1; let OC_TARGET_WINDOWS_X86_64: i32 = 2; let OC_TARGET_MACOS_X86_64: i32 = 3; let OC_TARGET_MACOS_AARCH64: i32 = 4;

Platform identifiers shared by occ --target (see OCC(1)) and sys_host_target(). OC_TARGET_OTHER denotes a POSIX host without a named target (FreeBSD, OpenBSD, NetBSD, DragonFly, Linux on non-x86_64 CPUs); the C backend still builds natively there with cc.

sys_host_target

extern fn sys_host_target() i32

Returns the OC_TARGET_* value of the platform the running binary was built for. With the C backend it is fixed when the generated C is compiled (from _WIN32, __APPLE__, __linux__, __x86_64__, __aarch64__), so bootstrap/occ_bootstrap.c built on any host reports that host. With --backend native it compiles to a single mov $target, %rax. occ itself uses it to pick the host C compiler, the shell convention for run, and whether \ is accepted in command-line paths.

Windows native runtime: Windows has no stable syscall ABI, so for --backend native --target windows-x86_64 the sys_* intrinsics are ordinary oC functions defined in std/sys/windows.oc, which the compiler appends to every such build. They call KERNEL32.dll through win32_<Name>(...), a call form the PE emitter lowers to an import using the Win64 calling convention. File descriptors 0, 1 and 2 are the standard streams; any other descriptor is the Win32 handle itself. O_APPEND and sockets are not supported there.

OC-MEM(3) — `std/mem.oc` Regional Arena Allocator

The std/mem.oc module implements pure kernel-backed contiguous bump memory regions. General-purpose heaps (such as ptmalloc or jemalloc) are discarded to eliminate heap fragmentation and metadata corruption (CWE-122).

struct Arena

struct Arena { offset: usize, capacity: usize, buffer: *mut u8 }

Regional allocator descriptor. Tracks the total allocated virtual memory size (capacity), the current high-water allocation mark (offset), and the base virtual address (buffer) returned by sys_mmap.

arena_init

fn arena_init(capacity: usize) Arena

Allocates a new virtual memory region of capacity bytes directly from the Linux kernel using anonymous private paging (sys_mmap(0, capacity, 3, 34, -1, 0)). Returns an initialized Arena with offset = 0.

arena_alloc

fn arena_alloc(arena: *mut Arena, size: usize) *mut u8

Carves out a contiguous slice of size bytes from the arena. Guarantees 8-byte alignment and executes an explicit capacity guard: if arena.offset + size > arena.capacity, it safely aborts or returns (0).as(*mut u8) to prevent out-of-bounds pointer fabrication.

arena_reset

fn arena_reset(arena: *mut Arena) void

Active Defense CWE-14 Scrubbing: Iterates across the allocated buffer from index 0 up to arena.offset, setting every byte to 0 to destroy transient cryptographic keys or passwords in RAM. Resets arena.offset = 0. Backing kernel pages remain mapped for high-throughput reuse. The compiler's EscapeValidator statically invalidates all previously borrowed pointers to this arena.

arena_deinit

fn arena_deinit(arena: *mut Arena) void

Performs CWE-14 zero-scrubbing across [0..arena.offset], unmaps the backing virtual memory pages via sys_munmap(arena.buffer, arena.capacity), and resets all struct fields to 0. Compile-time EscapeValidator treats attempts to read pointers allocated from this arena after deinit as fatal (CWE-416 Use-After-Free).

Example: Regional Memory Allocation & CWE-14 Scrubbing
SRC: arena_usage.oc 
import "std/mem.oc";

fn main() {
    // 1. Initialize a 64 KB regional arena backed by sys_mmap
    let mut arena: Arena = arena_init(65536);

    // 2. Fast bump allocation (no per-allocation metadata)
    let chunk: *mut u8 = arena_alloc(&mut arena, 16);
    chunk[0] = 79; // 'O'
    chunk[1] = 67; // 'C'
    print(chunk[0]);
    print(chunk[1]);

    // 3. Reset arena (scrubs memory with zeroes, resets bump pointer)
    arena_reset(&mut arena);

    // 4. Deallocate and return pages to kernel
    arena_deinit(&mut arena);
    print("Arena deallocated safely.");
}
TERMINAL: Output 
$ occ run arena_usage.oc
79
67
Arena deallocated safely.
Lifetime Invariant: Attempting to access chunk[0] after arena_reset(&mut arena) or arena_deinit(&mut arena) causes occ to reject compilation with error: use-after-free: variable 'chunk' used after arena 'arena' was reset/deinitialized.

OC-FS(3) — `std/fs.oc` Hardened File System I/O

The std/fs.oc module enforces active defense against TOCTOU symlink races (CWE-367 / CWE-59), file descriptor leaks into child processes (CWE-403), and missing path null-terminators (CWE-170).

cstr_path

fn cstr_path(path: string, out_buf: *mut u8) *u8

Mitigates CWE-170 (Improper Null Termination). Takes an immutable slice path: string, copies up to 4095 bytes into stack buffer out_buf: [4096]u8, and explicitly writes a terminating \0 at out_buf[len]. Guarantees kernel path arguments never read uninitialized stack bytes.

read_file

fn read_file(path: string, out_buf: *mut u8, max_len: usize) i64

Opens file at path with flags 0 | 655360 (O_RDONLY | O_NOFOLLOW | O_CLOEXEC). O_NOFOLLOW guarantees symlinks are rejected to prevent redirection attacks. O_CLOEXEC guarantees the descriptor is closed if execve is called. Reads up to max_len bytes into out_buf, closes the descriptor, and returns bytes read.

write_file

fn write_file(path: string, content: string) bool

Opens or creates file at path with flags 577 | 655360 = 655937 (O_WRONLY | O_CREAT | O_TRUNC | O_NOFOLLOW | O_CLOEXEC) and mode 420 (octal 0644). Writes content.len bytes directly via sys_write, safely closes the descriptor, and returns true if all bytes were written.

chmod_exec

fn chmod_exec(path: string) bool

Changes permissions of the target file to executable (mode 493 decimal = 0755 octal) via sys_chmod. Returns true on success.

unlink_file

fn unlink_file(path: string) bool

Removes the target file from the filesystem using sys_unlink. Returns true if unlinking succeeded.

Example: Atomic File Write, Hardened Read & Unlink
SRC: secure_fs.oc 
import "std/fs.oc";

fn main() {
    let file_path: string = "/tmp/oc_secure.txt";
    
    // 1. Atomic write with O_NOFOLLOW | O_CLOEXEC (CWE-367 / CWE-403)
    let written: bool = write_file(file_path, "oC Active-Defense Filesystem");
    print("File write status:");
    print(written);

    // 2. Safe read with 4096-byte bounded path buffer (CWE-170)
    let mut buf: [64]u8 = [0];
    let bytes: i64 = read_file(file_path, (&mut buf).as(*mut u8), 63);
    if bytes > 0 {
        buf[bytes.as(usize)] = 0;
        print("Read content:");
        print(buf);
    }

    // 3. Securely unlink temporary artifact
    let unlinked: bool = unlink_file(file_path);
    print("Unlink status:");
    print(unlinked);
}
TERMINAL: Output 
$ occ run secure_fs.oc
File write status:
true
Read content:
oC Active-Defense Filesystem
Unlink status:
true
Linear Resource Analysis (planned, not implemented): the compiler does not track file descriptor lifecycles yet. Closing a descriptor twice (CWE-415 / CWE-675) or returning without closing it (CWE-404 / CWE-775) is not diagnosed; close every descriptor you open.

OC-STR(3) — `std/str.oc` Strings

A string is a {ptr, len} view of bytes; nothing here relies on a NUL terminator. Three rules hold throughout: functions that only look at a string return slices of their input and never allocate; functions that build a new string take an Arena, so the validator rejects using the result after that arena is reset or deinitialized; and running out of arena space panics with panic: arena out of memory instead of returning a null view. Classification is ASCII only.

Comparison and views

fn str_eq(a: string, b: string) -> bool
fn starts_with(s: string, prefix: string) -> bool   fn ends_with(s: string, suffix: string) -> bool
fn find(s: string, needle: string) -> i64   fn contains(s: string, needle: string) -> bool
fn trim(s: string) -> string   fn trim_start(s: string) -> string   fn trim_end(s: string) -> string
fn substr(s: string, start: usize, len: usize) -> string
fn split_once(s: string, sep: string, out: *mut Split) -> bool   struct Split { head: string, tail: string }
fn cstr_to_string(cstr: *u8) -> string

find returns the index of the first occurrence, or -1; an empty needle is found at 0. trim removes ASCII whitespace (space, tab, newline, vertical tab, form feed, carriage return) from both ends. substr panics with slice index out of bounds when the range leaves the string. split_once fills out with the parts before and after the first separator and returns true, or returns false with out.head set to all of s. It uses an out parameter because the native backend returns at most 32 bytes, and {ok, head, tail} would be 40.

ASCII classification

fn is_digit(c: u8) -> bool   fn is_alpha(c: u8) -> bool   fn is_space(c: u8) -> bool   fn is_upper(c: u8) -> bool   fn is_lower(c: u8) -> bool
fn to_upper(c: u8) -> u8   fn to_lower(c: u8) -> u8

Bytes of 128 and above are neither letters, digits nor spaces, and to_upper / to_lower leave them unchanged.

Building strings in an arena

fn str_concat(arena: *mut Arena, a: string, b: string) -> string
fn str_repeat(arena: *mut Arena, s: string, n: usize) -> string
fn str_join(arena: *mut Arena, parts: *string, count: usize, sep: string) -> string
fn str_replace(arena: *mut Arena, s: string, from: string, to: string) -> string
fn str_to_upper(arena: *mut Arena, s: string) -> string   fn str_to_lower(arena: *mut Arena, s: string) -> string
fn str_alloc(arena: *mut Arena, n: usize) -> *mut u8

str_join takes a pointer to an array of strings: str_join(&mut a, (&words).as(*string), 3, ", "). str_replace replaces every non-overlapping occurrence from left to right; an empty from matches nothing. An empty result is "" and allocates nothing. 

import "std/str.oc";

fn main() {
    let mut a: Arena = arena_init(4096);
    let mut kv: Split = Split { head: "", tail: "" };
    if split_once("  name = Ada ", "=", &mut kv) {
        print(str_concat(&mut a, "Hello, ", trim(kv.tail))); // Hello, Ada
    }
    arena_deinit(&mut a);
}

OC-IO(3) — `std/io.oc` Standard Input & Output

The std/io.oc module handles standard streams without format string vulnerabilities (CWE-134). Input is returned as plain values: the compiler does not track untrusted (tainted) data, so validate it before using it as a path, length or index.

print / println

fn print(val: T) void
fn println(s: []u8) void

Safe stdout emitter. Emits slices, strings, integers, and booleans directly via sys_write(1, ...). Because print does not accept runtime C-style format strings (%s, %n), format string injection (CWE-134) is impossible by construction.

print_f64 (std/fmt.oc)

fn print_f64(x: f64, digits: u32)

print shows a float with six decimals (3.750000, or 9.007199e+15 in scientific form). print_f64 prints x with digits significant digits (1 to 40) in the format of C's printf("%.digitsg\n", x): fixed notation when the decimal exponent is between -4 and digits, scientific otherwise, trailing zeros removed. 17 digits always identify an f64 exactly: print_f64(0.1, 17) prints 0.10000000000000001. The digits are correctly rounded (halves to even) because they come from the exact decimal value of x. NaN, infinities and negative zero print as with print. It lives in its own module because the exact conversion adds about 10 KB to a native binary.

read_int

fn read_int() i32

Reads characters directly from standard input (fd = 0) using sys_read, filters ASCII characters between '0' (48) and '9' (57), and builds an integer. Ignores trailing newlines and non-numeric characters. The result is an ordinary i32: validate it before using it as a length, index or path.

Example: Formatted Stream I/O & Numeric Extraction
SRC: io_demo.oc 
import "std/io.oc";

fn main() {
    print("Enter numeric configuration port: ");
    let port: i32 = read_int();
    print("Parsed configuration integer:");
    print(port);
}
TERMINAL: Interactive Run 
$ occ run io_demo.oc
Enter numeric configuration port: 8080
Parsed configuration integer:
8080
Dataflow Taint Tracking (planned, not implemented): values read via sys_read or read_int are ordinary values. The compiler does not yet stop them from reaching file paths or slice indices unvalidated; bounds and overflow checks still apply at run time.

OC-NET(3) — `std/net.oc` Raw Socket & Wire Primitives

The std/net.oc module exposes raw Linux socket syscalls and byte-order serialization utilities for network protocol implementations and security probes.

packed struct sockaddr_in

packed struct sockaddr_in { sin_family: u16, sin_port: u16, sin_addr: u32, sin_zero: [8]u8 }

16-byte packed structure matching the Linux kernel struct sockaddr_in memory layout. The packed keyword prevents the compiler from inserting alignment padding bytes, preventing uninitialized memory disclosures (CWE-200) across socket boundaries.

htons

fn htons(hostshort: u16) u16

Converts 16-bit integer values from host byte order (little-endian on x86_64) to network byte order (big-endian) by transposing the high and low bytes.

probe_port

fn probe_port(port: u16) bool

Creates an AF_INET (2) TCP socket via sys_socket(2, 1, 0), configures sockaddr_in to target localhost (127.0.0.1 = 0x0100007f) on htons(port), attempts sys_connect, and immediately closes the socket with sys_close. Returns true if the port is open and listening.

Example: Network Socket Prober & Big-Endian Wire Conversion
SRC: net_probe.oc 
import "std/net.oc";

fn main() {
    let p: u16 = 8080;
    let net_order: u16 = htons(p);
    print("Host order 8080 to network order:");
    print(net_order);

    // Probe local port for listener (e.g. port 9999)
    let is_listening: bool = probe_port(9999);
    print("Port 9999 active:");
    print(is_listening);
}
TERMINAL: Output 
$ occ run net_probe.oc
Host order 8080 to network order:
36903
Port 9999 active:
false
ABI Wire Safety: sockaddr_in is declared packed so the compiler produces zero uninitialized padding gaps between sin_port and sin_addr, eliminating kernel/stack information leaks (CWE-200 / CWE-457).

OC-MATH(3) — `std/math.oc` Checked Mathematical Helpers

The std/math.oc module provides integer, fixed-point and floating-point math. The integer functions follow oC's rule for arithmetic: a result that does not fit panics. Behaviour that deliberately differs is in the name (sat_* saturates, the checksums wrap). The f64 functions follow IEEE 754 instead: they never panic, and an invalid input gives NaN or infinity.

Integer limits

let I8_MIN, I8_MAX: i8   let I16_MIN, I16_MAX: i16   let I32_MIN, I32_MAX: i32   let I64_MIN, I64_MAX: i64
let U8_MAX: u8   let U16_MAX: u16   let U32_MAX: u32   let U64_MAX: u64   let USIZE_MAX: usize

The smallest and largest value of each integer type (the unsigned minimum is 0). One step beyond any of them panics with integer overflow. A literal works too: -9223372036854775808 is the most negative i64, so -9223372036854775807 - 1 is not needed.

min, max, clamp, abs, sign

fn min_T(a: T, b: T) -> T
fn max_T(a: T, b: T) -> T
fn clamp_T(x: T, lo: T, hi: T) -> T
fn abs_i32(x: i32) -> i32   fn abs_i64(x: i64) -> i64
fn sign_i32(x: i32) -> i32   fn sign_i64(x: i64) -> i32

There are no generics yet, so each function names its type: T is one of i32, i64, u32, u64, usize. abs of the most negative value has no result and panics with integer overflow (in C it silently returns the same negative number). clamp requires lo <= hi.

Number theory and powers

fn gcd_u64(a: u64, b: u64) -> u64   fn lcm_u64(a: u64, b: u64) -> u64
fn pow_u64(base: u64, exp: u64) -> u64
fn pow_mod_u64(base: u64, exp: u64, m: u64) -> u64   fn mul_mod_u64(a: u64, b: u64, m: u64) -> u64
fn isqrt_u64(n: u64) -> u64   fn ilog2_u64(n: u64) -> u32
fn is_pow2_u64(n: u64) -> bool   fn next_pow2_u64(n: u64) -> u64
fn div_ceil_u64(a: u64, b: u64) -> u64
fn align_up(addr: usize, alignment: usize) -> usize   fn align_down(addr: usize, alignment: usize) -> usize

lcm_u64, pow_u64, next_pow2_u64 and align_up panic when the result does not fit. pow_mod_u64 and mul_mod_u64 never overflow, for any 64-bit modulus. isqrt_u64 is the exact floor of the square root for every u64. ilog2_u64(0) panics. align_up replaces the former align_forward and works for any alignment above zero.

Bit manipulation

fn popcount_u64(x: u64) -> u32   fn clz_u64(x: u64) -> u32   fn ctz_u64(x: u64) -> u32
fn rotl_u32 / rotr_u32(x: u32, n: u32) -> u32   fn rotl_u64 / rotr_u64(x: u64, n: u32) -> u64
fn bswap16(x: u16) -> u16   fn bswap32(x: u32) -> u32   fn bswap64(x: u64) -> u64
fn bit_get(x: u64, n: u32) -> bool   fn bit_set / bit_clear(x: u64, n: u32) -> u64
fn bits_extract(x: u64, lo: u32, width: u32) -> u64

Building blocks for registers, protocol fields, CRCs and hashes. clz_u64(0) and ctz_u64(0) are 64. Rotation counts are taken modulo the width. Bit indices must be below 64, and lo + width must not exceed 64.

Saturating arithmetic

fn sat_add_T(a: T, b: T) -> T   fn sat_sub_T(a: T, b: T) -> T   fn sat_mul_T(a: T, b: T) -> T

For T in i16, i32, u8, u16. The result is clipped to the range of the type instead of panicking, which is what audio and control loops want.

Fixed point (Q15, Q31) and integer sine / cosine

fn q15_mul(a: i16, b: i16) -> i16   fn q15_mul_round(a: i16, b: i16) -> i16   fn q15_add(a: i16, b: i16) -> i16
fn q31_mul(a: i32, b: i32) -> i32
fn q15_from_i32(x: i32) -> i16   fn q15_to_i32(q: i16) -> i32
fn sin_q15(angle: u16) -> i16   fn cos_q15(angle: u16) -> i16

A Q15 number is an i16 holding value × 215, so it covers [-1, 1) in steps of 1/32768; Q31 is the same in an i32. All operations saturate. sin_q15 and cos_q15 use CORDIC (shifts and adds only) and take a binary angle: 65536 units per turn, so 16384 is 90 degrees and a u16 phase accumulator wraps exactly once per turn. They are accurate to within one Q15 step.

Checksums and hashes

fn crc16_ccitt(data: string) -> u16
fn crc32(data: string) -> u32
fn fnv1a_64(data: string) -> u64

CRC-16/CCITT-FALSE (polynomial 0x1021, initial value 0xFFFF; "123456789" gives 0x29B1), CRC-32 as used by zip and PNG ("123456789" gives 0xCBF43926), and 64-bit FNV-1a. These are modular by design and use the wrapping_* built-ins internally.

Floating point: classification, comparison and rounding

let PI, TAU, E, SQRT2, LN2: f64
fn is_nan(x: f64) -> bool   fn is_inf(x: f64) -> bool   fn is_finite(x: f64) -> bool
fn approx_eq(a: f64, b: f64, eps: f64) -> bool
fn fabs_f64(x: f64) -> f64   fn fmin_f64 / fmax_f64(a: f64, b: f64) -> f64   fn copysign_f64(x: f64, y: f64) -> f64
fn floor_f64 / ceil_f64 / trunc_f64 / round_f64(x: f64) -> f64

== is not allowed on floats, so approx_eq is how two floats are compared: it is true when |a - b| <= eps, and false if either is NaN. round_f64 rounds halves away from zero (2.5 becomes 3, -2.5 becomes -3). The rounding functions return a float; to get an integer, cast the result with .as(i64), which panics if it does not fit. fmin_f64 and fmax_f64 ignore a NaN argument and return the other one. copysign_f64 treats a negative zero y as positive.

Floating point: elementary functions

fn sqrt_f64(x: f64) -> f64   fn hypot_f64(x: f64, y: f64) -> f64
fn sin_f64 / cos_f64 / tan_f64(x: f64) -> f64
fn atan_f64(x: f64) -> f64   fn atan2_f64(y: f64, x: f64) -> f64
fn exp_f64(x: f64) -> f64   fn log_f64(x: f64) -> f64   fn log10_f64(x: f64) -> f64
fn pow_f64(x: f64, y: f64) -> f64   fn pow2_f64(n: i64) -> f64

Angles are in radians. These are written in oC with + - * / only (sqrt_f64 is the processor's instruction), so both backends give bit-identical results and no C math library is linked. Measured against the C library on 200,000 inputs per function: sin, cos, atan, atan2, exp and log are within 1 ulp (one step of the last binary digit); tan, log10 and hypot within 2 ulp; sqrt is exact.

Limits worth knowing: sin_f64 and cos_f64 have that accuracy for |x| up to 106. Beyond it the absolute error grows to about |x| × 1.1e-16, and from 252 the result is NaN, so keep a running phase wrapped to one turn rather than letting it grow. pow_f64 is exact for integer exponents whenever the result is representable (pow_f64(2.0, 10.0) is exactly 1024) and accurate to about 10-13 relative otherwise; a negative base with a non-integer exponent gives NaN. log10_f64 of an exact power of ten can be one step off (log10_f64(1.0e15) is 14.999999999999998), so round it before casting to an integer. log_f64 of a negative number is NaN and of zero is -inf; under --fp-trap those panic instead. Reading a float from text (parse_f64) is not provided yet.

Example: Alignment, Checked Absolute Values & a Filter Response
SRC: math_demo.oc 
import "std/math.oc";

fn main() {
    let aligned: usize = align_up(17, 8);
    print("Align 17 up to an 8-byte boundary:");
    print(aligned); // 24

    let abs_val: i32 = abs_i32(-42);
    print("Absolute value of -42:");
    print(abs_val); // 42

    let minimum: u32 = min_u32(100, 45);
    print("min_u32(100, 45):");
    print(minimum); // 45

    // RC low-pass filter: R = 1 kOhm, C = 100 nF, input at 5 kHz.
    let w_rc: f64 = TAU * 5000.0 * 1000.0 * 1.0e-7;
    print("RC filter gain in dB and phase in degrees at 5 kHz:");
    print(20.0 * log10_f64(1.0 / hypot_f64(1.0, w_rc))); // -10.362137
    print(-atan_f64(w_rc) * (180.0 / PI));               // -72.343213
}
